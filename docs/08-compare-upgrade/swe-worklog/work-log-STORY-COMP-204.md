## 1. Problem Addressed
In previous runs, crosswalk judgments exhibited:
1. Conflation of "Enables/Supports" with "Satisfies/Covers", leading to a skewed `SUPERSET_OF` distribution (~77.4%).
2. Lack of independent assurance coverage dimension (`FULL_COVERAGE`, `PARTIAL_COVERAGE`, `NO_COVERAGE`).
3. Directional ambiguity when relating source regulatory clauses to framework controls.

## 2. Implementation Summary
1. **Two-Dimensional Evaluation Model**:
   - `TwoDimensionalEvaluation` dataclass in `backend/app/services/nli_evaluator.py` capturing:
     - `semantic_relation`: `[EQUIVALENT, SUBSET_OF, SUPERSET_OF, OVERLAPS, SUPPORTS, NONE]`
     - `assurance_coverage`: `[FULL_COVERAGE, PARTIAL_COVERAGE, NO_COVERAGE]`
     - `confidence`: float (0.0 to 1.0)
     - `rationale`: Verbatim audit justification
   - Provided backward compatibility alias and `.relation` property for legacy consumers.
2. **Dual-Judge NLI Prompt Calibration**:
   - Explicitly decoupled conceptual overlap from audit satisfaction.
   - Resource allocation/budgeting controls automatically assigned `SUPPORTS` + `NO_COVERAGE`.
3. **Pipeline Upgrade**:
   - Updated `scripts/run_production_evaluation_suite.py` to evaluate all candidate pairs generated by `HybridCandidateRetriever` with `filter_active_controls`.
   - Dual-write to PostgreSQL (`semantic_relation`, `assurance_coverage`, `status`, `rationale`) and Memgraph (`:CROSSWALKS_TO`).
